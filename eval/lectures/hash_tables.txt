A hash table stores key-value pairs and supports insertion, deletion, and lookup in average constant time. A hash function maps each key to an index in an underlying array of buckets. A good hash function spreads keys uniformly so that few keys land in the same bucket. A collision happens when two different keys are mapped to the same index. Separate chaining handles collisions by storing a linked list of entries in each bucket. Open addressing handles collisions by probing other slots in the array until an empty one is found. Linear probing checks the next slot in order, which can create long clusters of occupied slots. The load factor is the number of stored entries divided by the number of buckets. When the load factor grows too high, performance degrades, so the table is resized and every entry is rehashed. Resizing is expensive, but because it happens rarely, the amortized cost of insertion stays constant. In the worst case, when every key collides, a lookup degrades to linear time. Python dictionaries and Java HashMaps are both built on hash tables.
